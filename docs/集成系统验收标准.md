# 集成系统验收标准

本文是系统集成（阶段 A–G）的验收与发布门槛总规范。历史模型（Bridge #29/#59/#22/#24/#27/#28）是**开发证据与回归样例**，不是任何代码路径的前提：通用代码不得包含数据集名、固定文件名、模型 ID、固定 ROI 或固定照片数。

## 1. 物理边界（对所有档位生效）

- 没有任何照片观察到的表面**不能**被经典多视图重建保证还原。系统只对"可观测且满足重叠条件的表面"承诺统一质量门槛。
- 没有顶部/高角度视角时：提交预检与结果必须显示"顶部视角不足/不可验证"提示（见 `mesh_quality.top_view_warning`），不得用 Poisson trim、外插或猜测封洞冒充修复。
- 所有质量代理指标（面支撑、投影覆盖、留出深度）**不是几何真值**；报告必须携带口径说明与单位（模型单位 ≠ 米）。

## 2. 通用硬门槛（任意输入集自动验证）

| 门槛 | 实现位置 | 判定 |
| --- | --- | --- |
| 配置冻结 | `job_service.create_job` → `profiles.resolve_job_config`；`PipelineContext` 只读 `config["resolved"]` | 执行与恢复不被环境变量漂移改变；旧任务（无 resolved）保持历史行为 |
| 提交预检 | `job_service._preflight_images` | 文件缺失在提交时失败（`INPUT_FILES_MISSING`）；预检如实记录 `view_overlap=unknown_until_registration` |
| auto 匹配 | `profiles.auto_matcher_decision` | 连续编号 → sequential；无序 → exhaustive；决策写入冻结配置与发布清单 |
| CUDA/GPU 门槛 | `profiles.gpu_capability_report` + `create_job` | 稠密任务无 CUDA → `CUDA_UNAVAILABLE`；请求的 GPU 索引不可见 → `GPU_INDEX_UNAVAILABLE`；稀疏任务不要求 |
| 引擎身份 | Worker `engine_identity.binary_sha256`；贴图工具 `implementation.binary_sha256` | 路径/版本相同不代表二进制相同 |
| 发布保护 | `workers/jobs._publish` CAS + 单事务 | 失败/取消不产生部分模型；恢复只生成正确后继 |
| 贴图一等证据 | `photo_texture` 元数据 | 记录注册照片数、atlas、贴图面率、工具哈希；失败明确 fallback 不冒充完整 |
| 原色贴图可用性 | `glb_assets.inspect_glb` → `ModelDetailOut.texture_assets` | 以 GLB 实际内嵌纹理 + UV 为准；旧记录回退 stage_origin；EV 只是预览，不改下载文件 |

## 3. 速度与质量门槛（场景特异性，需按协议复测）

- **速度**：同输入、同引擎，单/双卡与 2000/3000 px 对照，每组 ≥3 次冷跑；分开记录队列、稠密、融合、网格、贴图、端到端。双卡门槛以"中位稠密加速 ≥1.7×（相对冻结单卡基线）"为候选值，按硬件/规模校准。South 40 固定 2000 px 的 1.99× 是一次受控观测，不是通用保证。
- **质量非劣**：候选相对保守 baseline 的注册率、视图覆盖、近点支撑、无支撑外插、网格/贴图覆盖不得恶化超过预声明容差；C01 组合提速在 Bridge 上覆盖略降（96.55%→94.19%）已如实记录，`speed` 画像以"通用可选画像"提供，由用户按质量-速度取舍。
- **网格候选**：`_stage_meshing` 按预声明门槛自动生成 trim-1 候选并裁定（上部带支撑 <0.7 时触发；支撑更高且无支撑增长 ≤3pp 才采用）。逐候选指标与裁定理由进入 MESHING manifest。
- **留出验证**：用未参与稠密训练的照片评估深度/覆盖；共享稀疏标定的局限必须写明（见 `docs/e7-bridge-evidence/` 协议）。

## 4. 区域提取（C）

- 语义永远是"现有网格的独立裁剪"，不称重建；`region_report.json` 记录 `crop_semantics=triangle-centroid`、`boundary_edges/boundary_open`、`texture_assets`（导出文件实测）与 `parent_sha256`。
- 支持已保存选区复用；结果详情提供"回父模型看选区"；父模型字节与下载哈希不变。

## 5. 局部更新（D）

| 层 | 门槛 | 拒绝行为 |
| --- | --- | --- |
| D1 注册 | 任意 1–32 张新增照片；`image_registrator` 注册到父稀疏模型；父位姿逐字保持；逐张报告 registered/failed | 注册数为 0 → 阶段失败，不产生几何 |
| D2 局部融合 | 视角集 = 注册新视角 + 距选区最近父视角（≤16）；新增点须在保护带核心盒内、≥min(2, 注册数) 视角深度一致、父距离窗内 | 父点记录前缀逐字节不变；否则失败 |
| D3 网格补丁 | 父侧保留按面中心裁剪（UV/材质字节随 visual 保留）；补丁 Poisson + 顶点级盒切；边界环弧长对齐缝合，缝隙 ≤3× 补丁中位边长；核心盒外父面逐字保留（坐标匹配）；非流形边 = 0 | 任一不过 → 只写 `mesh-patch-report.json`，不发布 GLB |
| D4 补丁着色 | 补丁顶点色取融合点云多视角颜色（非图集），父侧贴图原样保留 | 无覆盖顶点回退中性灰并在 manifest 标注 |

种子模式（`local_reconstruct`，三张预注册照片）保留为历史兼容实验模式；通用主路径是 `local_general` / `local_mesh`，不再读取固定种子文件。

**真实 GPU 验收结论（2026-11-21）**：双卡加速在 Bridge 与 South 双场景通过（1.988× / 1.966×，各 3+3 轮，通过 ≥1.7× 门槛）。D1/D2 在双场景通过（逐张注册报告、父位姿逐字不变、父记录前缀保护）。（逐张注册报告、父位姿逐字不变、父记录前缀保护）。D3 的环-弧长缝合在两场景的真实父网格上均被门槛诚实拒绝——父网格天然洞与补点价值区重合，边界环对应普遍不适定；通用 D3 需重叠带约束重网格化，在实现前 D3/D4 不宣称通过，交付名不含「最终集成版」。

## 6. 测试分层（F3）

| 层 | 覆盖 | 命令 |
| --- | --- | --- |
| 后端单元/集成 | profile 解析、auto 匹配、提交门槛、GLB 资产、网格质量、区域报告、通用局部冻结、网格补丁几何与提交 | `cd backend && pytest -q`（本轮 175 项） |
| 前端 | 任意照片选择、原色可用性、点云/网格字段、补丁提交、模式切换 | `cd frontend && npm test && npm run build` |
| 真实浏览器夹具 | Chromium + 前端生产构建：切换导航、父版选区、已保存选区复用、补丁提交、下载哈希 | `python scripts/phase8_gui_test.py --dist <构建> --screenshots <目录>` |
| 真实 HTTP/队列 | 隔离 API + Redis + Worker + `e2e_test.py`（含 speed 画像与 auto 决策） | `scripts/e2e_test.py --base-url ... --preset speed` |
| 真实 GPU | 双卡稠密、3000 px、局部注册+融合、留出深度 | 需按 §3 协议在隔离环境执行；本轮 D1–D4 尚未做真实 GPU 端到端，发布集成候选前必须补 |

夹具与真实证据分开报告；历史站点（`18082`/`18469`/`18479`）不被本轮源码覆盖。

**部署要点（实测发现）**：稠密阶段对 scratch 位置极其敏感——NFS 家目录使单次稠密迭代膨胀 3.4×（4.8s→16s），导致 speed 画像无法复现 48 分钟；`SCRATCH_DIR` 指向本地盘后稠密 1960s ≈ C01 的 1965s、整轮 50.7 分钟 ≈ 48 分钟。部署时 `SCRATCH_DIR` 必须指向本地盘。

**环境启停统一用 `scripts/acceptance_env.sh`**（隔离 Redis + API + N 个 Worker 的单环境管理器）：`start|stop|status` 三命令；启动后通过 /proc 扫描按「cmdline + environ（DATABASE_URL/端口）」双指纹捕获真实 PID 写 pid 文件（不依赖 setsid 包装 PID），停止时 pid 文件中的陈旧 PID 需先过指纹确认——历史站点（18082/18469/18479 等）进程永远不会被误杀；`SCRATCH_DIR` 默认 `/tmp/recon-<环境名>-scratch`（本地盘）；写 `env.json` 环境指纹（端口/scratch/GPU/二进制路径/真实 PID）供追溯。示例：

```bash
bash scripts/acceptance_env.sh --env ../integrated-acceptance.bridge \
  --port 18497 --redis 18498 --gpu-index "0,1" --dense-size 3000 start
```

## 7. 交付命名

在真实 GPU 验证（§6 最后一行）通过前，不得称"最终集成版"；只能称"通用主重建 + 通用区域提取 + 通用局部点云候选 + 网格补丁候选（待真实场景验收）"。
