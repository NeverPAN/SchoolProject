# 图片三维重建系统｜课程设计报告提纲

本提纲按课程《课程设计报告参考提纲》及[开发指南 §18.3](../DEVELOPMENT_GUIDE.md)组织。它是写作与取证清单；结合现有证据撰写的报告见[课程设计报告正文](course-report.md)。已验收、原型、估算和待补测必须分别标注。报告引用任务号时一并写明数据集、配置和验收轮次，避免把不同环境中的任务号或模型号混在一起。

## 一、实验报告封面

填写题目《基于 COLMAP 的多视角图片三维重建与 Web 模型管理系统》、课程、指导教师、小组成员及学号、提交日期和版本。答辩稿与存档稿沿用同一题目；不在公开材料中放账户、口令、令牌或访问凭据。

## 二、摘要（150–300 字）

独立成文，不放图表。依次说明要解决的问题、技术路线与实验条件、关键实测结果、结论和工程贡献。建议选“Bridge 百图真实浏览器闭环”和“South 固定 2000 px 的双卡稠密阶段对照”各一个结果，注明测试条件；区域提取只作为探索原型，不写成已实现的新照片局部重建。

## 三、关键词（3–6 个）

建议：多视角三维重建；COLMAP；稠密重建；GPU 加速；断点恢复；Web 模型展示。

## 四、引言 / 研究背景

- 说明建筑或文物数字化等应用场景，以及原图管理、长任务诊断、失败恢复和浏览器预览的工程难点。
- 简述经典 SfM/MVS、Poisson 网格化和学习式/高斯表示路线；说明本项目选择成熟的 COLMAP 工具链和可下载的网格/点云，而非重新实现底层算法。见[相关工作](dev-summary/07-related-work.md)。
- 给出目标和范围：基本重建闭环、可靠性、性能与质量验证；追加照片按全量重跑发布新版本；区域提取与真实局部重建分别说明。工程贡献可写输入到产物的追溯、可校验恢复、Web 预览与实测对照。按实际贡献列成员分工。

## 五、实验原理与理论基础

- 解释 SIFT 特征、匹配与几何验证、SfM 相机估计和三角化、Bundle Adjustment 与重投影误差、去畸变、PatchMatch MVS、深度图融合、Poisson 网格化、照片贴图与 GLB 导出；给出实际使用的[重建流程](reconstruction-pipeline.md)。
- 说明浏览器、FastAPI、数据库/持久化文件、Redis/RQ 与独立 Worker 的分工；解释任务状态与按阶段估算的进度、输入/参数/引擎与输出校验如何约束恢复、如何区分任务和模型版本。以[架构](architecture.md)、[API 契约](api-contract.md)和[数据库设计](database-design.md)为依据。
- 定义注册率（注册照片数 / 输入照片数）、稠密阶段加速比（对照耗时 / 实验耗时）、重投影误差（像素单位）、投影覆盖与点支撑（附分子、分母、视图抽样和分辨率）、贴图面率（有照片贴图的面数 / 总面数）。点数、面数、二维覆盖和视觉效果不能代替几何真值误差。

## 六、实验设备、材料与实验环境

列明学校 Ubuntu 容器、NVIDIA A800 80 GB、各轮实际使用的 GPU 数，记录可见 CPU、内存及磁盘条件和共享负载情况；软件列实际版本和构建（例如 CUDA COLMAP 3.13.0、CPU 贴图 COLMAP 4.2.1），区分规划使用的 PostgreSQL 与隔离验收实用的 SQLite。见[环境报告](environment-report.md)和[部署文档](deployment.md)。

按用途区分小规模流程样本、South Building 40 张试验集和 ETH3D Bridge 100 张正式集。正式集按文件名排序取前 100 张原始 DSLR JPEG，未重编码，总计 920,566,231 字节；记录数据来源、获取许可、筛选规则、[SHA-256 清单](phase2-evidence/bridge100.sha256)与分辨率。Mock 与真实重建分别列实验环境。

## 七、实验方案与实验步骤

1. 固定代码版本、环境、输入清单和参数；记录任务 ID、引擎版本、卡数、稠密长边、预设、Poisson 参数与贴图开关。按[用户手册](user-manual.md)走上传、质量检查、提交、查看与下载，保存任务/阶段日志、产物及下载校验记录。
2. 对性能实验明确自变量（如 GPU 数或稠密长边）、因变量（阶段耗时、任务墙钟、资源和质量指标）和控制变量。墙钟统计从任务开始执行到成功发布，不含上传、排队和下载。写明采样频率、开始/结束时点、单位、重复次数；缺测写“未采集”，估算单列并说明方法。计划补测尽量每组重复三次，不把计划次数写成实测次数。见[测试计划](testing-plan.md)和[GPU 实验设计](dev-summary/11-gpu-resolution-benchmark.md)。
3. 对可靠性与版本实验分别设计取消/恢复、输入变更拒绝、版本成功/失败和旧文件校验。故障演练在隔离环境并经授权执行；不在在线演示服务上强杀进程。区域提取用例检查选区、异步任务、独立结果与原模型；局部重建 E7 另列验收条件，不用提取结果充数。

## 九、实验结果分析与讨论

- 将稠密阶段加速与端到端收益分开讨论，解释 CPU 融合、网格、贴图等仍需耗时。对 Bridge 只能按整体配置解释，不能据此推导固定分辨率加速。注明重复不足、共享负载及独立稀疏解带来的波动。
- 讨论分辨率、点云支撑、Poisson 参数与孔洞之间的关系：分辨率较高可能增加网格投影覆盖，但也可能降低贴图面率、增加资源消耗或外插；不要把高点数、高面数或贴图效果等同于更高精度。区分早期质量诊断指标与统一抽样复测指标。
- 讨论异常案例和局限：贴图尺寸超限后的重试，缺乏可靠朝向时的回退，反光/植被/窗洞导致的缺面，资源采样间隔遗漏的瞬时峰值，以及没有几何真值时不能给出绝对精度。引用理论或文献支持机制，不把不同数据和环境下的结果当作直接对照。

## 十、实验结论

按“系统闭环、工程可靠性、条件化的性能和质量权衡”逐条写已被证据支持的结论。明确结论适用的数据集、配置和任务范围；不宣称存在通用最优参数。把版本更新验证和区域提取原型作为单独成果，不宣称真正的局部几何重建、边界融合或分布式调度已经实现。

## 十一、实验不足与改进方案

- 补齐 Bridge 双卡 2000 px 固定分辨率对照和其余缺失配置，扩大重复次数，记录完整资源序列；具体优先级见[补测建议](dev-summary/建议补测.md)。
- 分别补齐追加失败后的旧版可用验证、冻结输入清单归因、真实多项目排队对照；第 8 阶段补真实模型浏览器从框选到查看/下载区域结果的闭环。真正局部更新另行评估新照片与原模型对齐、深度图复用、边界融合及选区外几何是否受损。
- 加入有参考几何的样本、同视角质量评价和重复测量，区分场景本身不可见的区域与算法误差。
