## 2. 测试体系（演进：50 → 73 项）

| 层级 | 内容 | 关键教训 |
| --- | --- | --- |
| 单元/API/管线 | pytest（73 项）：认证、隔离、上传、状态机、恢复、取消、下载魔数、并发 | 失败必须定位到阶段+错误码；不允许不可解释状态 |
| 端到端 | 真实 COLMAP+GPU 全链路（40/100 张） | 只认真实数据；合成数据不配做 SfM 验收 |
| GUI | Playwright/Chromium 夹具 + 真服务两种 | 画布像素断言 + 交互 + 下载哈希；大模型在软件渲染下要放宽"帧稳定"判据 |
| 故障演练 | 取消、强杀、孤儿清理、恢复 | 先清理遗留进程再恢复；结果落 JSON 证据 |
| 备份恢复 | SQLite WAL 隔离恢复 + 篡改拒绝 | 双端 integrity_check |
| 质量指标 | 同视角诊断 / sweep（z-aware） | 面数、边界边数、连通分量都不是质量；外插必须单列 |
| 性能对照 | 同云同机单次对照（Poisson 线程） | 如实标注"单次观测"；资源采样注明覆盖区间 |

**指标陷阱备忘**（本轮实测踩过）：
1. 固定像素 splat 半径跨分辨率不可比——半径须随工作分辨率缩放；
2. 面中心 splat 低估粗网格面积——改面积加权采样；
3. 多边形填充无法区分前/背面——必须 z-aware；
4. "连续两帧稳定"判据在软件渲染大模型下永不满足——改前景掩码面积/包围盒判据。

## 3. 文档规范（今后开发必须遵守）

> 已写入 [AGENTS.md](../../AGENTS.md)，对任何人（含 AI Agent）生效。

1. **每个开发阶段/轮次结束必须写总结文档**，放在 `docs/`，并更新 [00-overview.md](00-overview.md) 索引。
2. 文档必须包含：目标、改动、**测试命令与真实结果**、问题与解决方案、未解决项与边界；引用证据文件（日志/JSON/截图）的具体路径。
3. **图文并茂**：架构/流程用 mermaid；对比图、截图放 `docs/dev-summary/assets/`（或证据目录），原始运行数据留在 `data/`（不入 Git），文档只引用其结论与必要截图。
4. **不得编造**：所有数字来自真实运行；标注采样区间、单次观测、口径差异（如"面片口径 vs z-aware 口径"）。
5. 验收口径变化（如"面覆盖"）必须同时给出旧口径数据，避免前后文档自相矛盾。
6. 每次交付的 commit message 包含：改动摘要、关键指标、测试结果。
7. 报告模板：完成内容 / 测试命令与结果 / 未解决问题 / 下一步建议（AGENTS.md 第 10 条）。
